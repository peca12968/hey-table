# Pantry Freight｜餐廳整包採購與運費試算

午餐備料還缺 2 片豬排、280 g 雞肉、3 顆蛋、360 g 生米、20 ml 醬油和 2 g 昆布。各家供應商的包裝、可供包數與運費不同。Pantry Freight 讀取 Prep Sheet 的原料缺口，列出能補足缺口且到貨總價最低的採購組合。

## 重跑午餐範例

Python 3.11 以上，僅使用標準函式庫。以下金額與庫存皆為合成資料。

```sh
python purchase.py examples/lunch.json examples/suppliers.json
```

| 方案 | 包數 | 貨款 | 運費 | 總計 |
| --- | ---: | ---: | ---: | ---: |
| depot 每項各買一包 | 6 | NT$141 | NT$29 | NT$170 |
| market 每項各買一包 | 6 | NT$158 | NT$35 | NT$193 |
| market 多買一包 NT$7 的醬油 | 7 | NT$165 | NT$0 | **NT$165** |

第三個方案剛好達到免運門檻，供應午餐後會多出 30 ml 醬油。若店家沒有空間存放多買的原料，可在供應商檔案的最外層設定 `"max_surplus": {"soy":5,"kombu":3,"grain":40,"cutlet":0,"chicken":20,"eggs":0}`。相同需求改選 depot 六包，總價 NT$170。若雞肉允許的剩餘量再降至 10 g，則需要買進 280–290 g，兩家 300 g 的包裝都無法滿足，程式會指出原因。

## 接上備料與入庫

1. 將 Prep Sheet 的 `prep.py` 報表存成 JSON。程式只購買 `action=purchase` 且需求大於可用庫存的材料。每個缺口為 `needed - available`，會重新依供應商的包裝計算包數。
2. 在供應商目錄填入幣別 TWD、各家基本運費 `shipping`、含門檻的免運貨款 `free_at`（無免運填 `null`），以及各個 SKU 的材料、單位、每包含量 `pack`、每包價格 `price`、可供包數 `stock`。包價為正整數新台幣。報表以同一種單位核對每項材料，分別列出採購量與剩餘量。
3. 查看每家貨款與運費，依實際到貨驗收。`--format quantities` 可輸出 Prep Sheet 庫存帳接受的材料數量對照，作為驗收草稿。試算只讀取檔案。要用示範資料重跑入庫流程，可用下面的整合演練。

```sh
python prep_demo.py ../prep-sheet
```

演練建立暫存 SQLite 帳本，記錄期初庫存，從兩張午餐訂單產生備料報表，接著依採購包裝把六種原料入帳。以同一到貨單號重送仍取回同一收據，再跑一次採購的金額為 **NT$0**。[跨專案演練](prep_demo.py)

## 選擇規則與驗證

採購目標依序為最低含運總價、最少包數。若兩者都相同，按 SKU 名稱遞增排列後，以包數向量的字典序決定，所以打亂輸入順序仍會得到同一份單。只在這次有缺口的材料中挑選；要限制囤貨，針對該材料指定可接受的剩餘量。

動態規劃逐項處理材料，保留目前已補足的量及各供應商距免運所需的貨款進度。達到免運門檻後，增加貨款不再改變該家的運費。固定運費的供應商只需記錄是否已用。對相同狀態，保留最便宜的貨款方案與相應包數；有剩餘量上限時保留實際買進量。有限庫存拆成可組合的二進位批數。最壞狀態數仍隨供應商數和免運門檻增加，適合單店小批次詢價。

```sh
python -m unittest -v
```

測試以獨立窮舉法逐一比較 **320 組合成詢價單** 的可行性、含運金額及同價選擇。另測試跨供應商拆單、加購多包達到免運、庫存不足、單位衝突及整數精確度。成功回傳 0，輸入錯誤回傳 2，無可行採購方案回傳 3。無解時數量輸出為空，避免下游誤收部分到貨。[採購演算法](purchase.py) · [獨立驗證](test_purchase.py)

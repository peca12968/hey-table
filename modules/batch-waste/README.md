# Batch Waste｜兩鍋白飯的班末成本

午班開班時有一鍋白飯 400 g，做第二鍋後又多 400 g。兩張單領料共 560 g，盤點應剩 240 g，實際秤出 200 g。店員有 30 g 的報廢紀錄，剩下的 10 g 需要追查。工具依先進先出追到兩鍋不同的原料成本，再核對整班金額。

| 午班收支 | 數量 | 成本（新台幣） |
| --- | ---: | ---: |
| 期初白飯 | 400 g | 18.00 |
| 本班入料並煮成白飯 | 400 g | 22.00 |
| 兩張單領用 | 560 g | 26.80 |
| 已登記報廢 | 30 g | 1.65 |
| 未解釋短差 | 10 g | 0.55 |
| 期末白飯 | 200 g | 11.00 |

第二張單領 200 g，先用完第一鍋剩下的 40 g，再使用第二鍋的 160 g。報表列出兩鍋的製作收據與分攤金額。期初加進貨為 40 元，扣除領用、報廢、短差後，剩餘成本為 11 元。

## 重跑午班

此工具使用 Python 3.12 標準函式庫。跨專案範例在暫存 SQLite 內用 Prep Sheet 建立兩筆進貨、兩筆製作與兩筆領用，並以本專案的 CLI 讀取這六張收據。

```sh
python demo.py ../prep-sheet
python -m unittest -v
```

## 核對自己的備料帳

以 `prep-sheet/ledger.py --db kitchen.db history` 匯出完整歷史。每張進貨收據在發票 JSON 以收據號碼為鍵，列出各原料的單位與整筆成本（分）。例如 `{"1":{"grain":{"unit":"g","cost_cents":1600}}}`。每張進貨或採購驗收的所有品項都須提供成本，包含零成本的材料。

班末盤點 JSON 用 `through_receipt` 標記最後一張收據，以 `components` 逐項列出單位、目前實際存量和已記錄的丟棄量。例如 `{"through_receipt":6,"components":{"rice":{"unit":"g","quantity":200,"discarded":30}}}`。用 `--after` 指定上班前的最後一張收據，或從空帳以 0 開始。

```sh
python close.py history.json invoices.json counts.json --after 2
```

逐項核對每筆異動是否能得到收據上的新結餘。製作時把消耗原料的成本移到半成品，領料時依先進先出扣除各批數量和成本。成本用精確分數表示，JSON 中字串 `"200/63"` 代表 200/63 分。班末短差按先進先出計價，再依短差中有紀錄及待追查的數量分攤成本。這個假設適用於盤點只有總數的情形。

多出的數量會顯示為尚未估價的溢餘。沒盤到的品項沿用帳面成本並列出品名。輸出供單班對帳使用，實物及報廢仍須依店家的庫存流程登記，程式使用唯讀匯出檔計算。測試以逐單位的獨立模型核對 300 組先進先出與耗損案例，也涵蓋半成品再加工、單位錯誤與缺漏的進貨成本。[備料收據來源](../prep-sheet/README.md) · [逐單位核對](test_close.py)

# Shift Vault｜單檔增量備份

一份每天匯出的二進位檔，第二天只在開頭插入一行說明。按固定長度切塊時，後面的資料整體位移，原有區塊難以重用。Shift Vault 依內容選擇邊界，把區塊存入 SQLite。每版的 SHA-256 即為還原時使用的快照 ID。

## 重現檔頭插入實驗

需要 Python 3.12，執行時只使用標準函式庫。在專案根目錄執行以下命令。

```sh
python demo.py
python -m unittest -v
```

範例使用固定種子產生 1 MiB 二進位檔，在檔頭加入 21 位元組，對同一種資料計算兩種方法新增區塊的內容大小。最後從資料庫還原兩版，各自與原始資料逐位元組比較。[重現程式](demo.py)

| 第二版備份 | 新增內容 | 沿用內容 |
| --- | ---: | ---: |
| 固定 4 KiB 分塊 | 1,048,597 B | 0 B |
| 依內容分塊 | 3,665 B | 1,044,932 B |

再次備份相同的第二版會得到同一快照 ID，新增內容為 0 B。表中的數字以區塊內容計算。SQLite 頁面、索引、快照順序與交易日誌另占空間。實際重用量取決於來源資料與修改位置。

## 備份自己的檔案

從一份已完成寫入的檔案開始。第一個參數指定備份庫目錄，首次備份會建立這個目錄。

```sh
python vault.py ./backup-store backup ./export.bin
python vault.py ./backup-store list
```

指令會輸出 JSON。`snapshot` 是原檔的 SHA-256，`added_bytes` 是這次新增儲存的區塊內容大小。把下列指令中的 `SNAPSHOT_ID` 換成要取回的版本。還原時會在輸出目錄建立暫存檔，驗證整份快照後才取代目的檔。

```sh
python vault.py ./backup-store restore SNAPSHOT_ID ./restored.bin
```

## 儲存與失敗處理

- 每次讀入 64 KiB，以 Gear 指紋逐位元組選擇切點，每塊介於 2 KiB 和 16 KiB，尾塊可以更短。同一塊完全相同的內容可跨檔案、跨版本共用。空檔也能備份與還原。
- 每次備份在一筆 SQLite 交易內寫入區塊和快照清單。兩個程序同時備份同一份資料時，第二個會等候寫入鎖，再從已提交的區塊去重。中途退出後，下次開啟備份庫時由 SQLite 復原交易日誌，因此備份庫需放在可寫入的位置。
- 還原會檢查區塊位置、每塊 SHA-256、總長度及整檔 SHA-256。區塊損壞或次序遭改動時，既有目的檔會保留。工具保存單檔內容，檔名與權限由呼叫端管理。請使用已寫完的匯出檔或檔案系統快照作為來源。
